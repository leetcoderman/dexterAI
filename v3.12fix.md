## 🔴 Critical Bugs

### BUG-001: GitHub Models — Wrong Model ID Format
**File:** `registry/registry.json` (lines 846–1078)
**Severity:** Critical — Models will fail at the API call

GitHub Models uses model IDs like `openai/gpt-4.1`, `deepseek/deepseek-r1`, `meta/llama-4-maverick-17b-128e-instruct-fp8`. However, the GitHub Models API (at `models.inference.ai.azure.com`) **uses different model ID formats** than what's listed in the registry.

Based on the [GitHub Models marketplace](https://github.com/marketplace/models), the correct model IDs for the Azure-hosted inference endpoint are:
- `gpt-4.1` not `openai/gpt-4.1`
- `gpt-4o` not `openai/gpt-4o`
- `DeepSeek-R1` not `deepseek/deepseek-r1`
- `Llama-4-Maverick-17B-128E-Instruct-FP8` not `meta/llama-4-maverick-17b-128e-instruct-fp8`
- etc.

The `org/model-name` format is a GitHub marketplace URL convention, not the actual inference API model ID. When the adapter calls `client.chat.completions.create({ model: req.modelId })`, it sends these incorrect IDs, causing `404 Model Not Found` errors.

### BUG-002: GitHub Models — `ghp_` Token Not Detected by Key Format Validator
**File:** `registry/registry.json` (line 28), `packages/shared-utils/src/validate-key-format.ts`
**Severity:** Critical

The registry declares `key_prefix: "ghp_"` for GitHub, and the Connection UI placeholders suggest `ghp_` or `github_pat_` tokens. However:

1. `detectProviderFromKey()` in `validate-key-format.ts` has NO entry for `ghp_` — meaning GitHub keys won't be auto-detected, and the mismatch warning in `Connection.tsx` won't fire for GitHub keys.
2. Users entering fine-grained tokens (e.g., `github_pat_`) also won't be detected.

### BUG-003: AbortController Never Wired to Streaming
**File:** `ipc/chat.ipc.ts` (lines 36–37), `ipc/provider.ipc.ts` (lines 113–114)
**Severity:** High — Cancel button doesn't actually stop API requests

An `AbortController` is created and stored in `ActiveChatRequests` / `ActiveRequests`, but its `signal` is **never passed to the adapter**. The `cancel` handlers call `abort()`, but since the signal isn't connected to the HTTP request or stream, cancellation has no effect — the API call continues until completion, wasting tokens and time.

### BUG-004: Database Schema Path Breaks in Production Builds
**File:** `main/db/database.ts` (line 20)
**Severity:** High — App may crash on first launch in packaged builds

```typescript
const schemaPath = join(__dirname, '../../src/main/db/schema.sql');
```

This path assumes a development directory structure. After `electron-vite` builds and packages the app, `__dirname` will be inside an ASAR archive with a different structure. The `../../src/` relative path won't resolve to the schema file, causing `readFileSync` to throw.

---

### BUG-005: OpenAI `execute()` Missing Error Try-Catch
**File:** `adapters/openai.adapter.ts` (lines 46–82)
**Severity:** High — Streaming errors crash the IPC handler

The OpenAI adapter's `execute()` method doesn't wrap the streaming `for await` loop in a `try-catch`. If the stream throws mid-way (e.g., network drop, rate limit after first chunk), the error propagates up uncaught. Compare: NVIDIA and GitHub adapters both have `try-catch` around their stream loops.

## 🔒 Security Vulnerabilities

### SEC-001: `sandbox: false` in BrowserWindow (HIGH)
**File:** `main/index.ts` (line 46)
Disables Chromium sandboxing. If an attacker injects malicious content into the renderer (e.g., via crafted markdown), they gain full Node.js access.

### SEC-002: Command Injection via `execute_command` Tool (MEDIUM)
**File:** `tools/tool-executor.ts` (lines 120-149)
Runs arbitrary shell commands via `exec()` with `shell: true`. Approval UI shows command string, but obfuscated commands could slip past user review.

### SEC-003: API Keys Could Leak via Error Messages (LOW–MEDIUM)
**File:** `adapters/base.adapter.ts` (lines 86-107)
`mapError()` forwards `err.message` directly. Some SDKs include API keys in error messages.

### SEC-004: `fs:writeFile` Allows Arbitrary Overwrites Within Project Root (LOW)
**File:** `ipc/filesystem.ipc.ts` (lines 158-172)
Any file within the project root can be overwritten including `.env`, `package.json`, build configs.

### SEC-005: Google API Key Exposed in URL Query Parameter (LOW)
**File:** `adapters/google.adapter.ts` (line 11)
API key sent as URL parameter — logged in server access logs, network monitoring.

### SEC-006: Memory Extraction Prompt Injection Risk (LOW)
**File:** `ipc/memory.ipc.ts` (line 78)
User message transcript injected verbatim into extraction prompt. Adversarial content could generate false memories.

### Step 6.1 — Clean up TTS temp files on startup
- **What:** Remove stale TTS audio files from the temp directory
- **Where:** `apps/desktop/src/main/index.ts`, add cleanup on app ready
- **How:**
  ```typescript
  import { join } from 'path'
  import { readdirSync, unlinkSync, statSync } from 'fs'
  import os from 'os'

  function cleanupTTSCache() {
    const tmpDir = join(os.tmpdir(), 'dexterai-tts')
    try {
      const files = readdirSync(tmpDir)
      const now = Date.now()
      for (const f of files) {
        const fp = join(tmpDir, f)
        const age = now - statSync(fp).mtimeMs
        if (age > 24 * 60 * 60 * 1000) unlinkSync(fp) // Older than 24h
      }
    } catch {}
  }
  ```
