## Problem

ModelForge has no NVIDIA NIM provider entry. Users who obtain an `nvapi-` key from `build.nvidia.com` have no correct path to connect it — the only apparent option is the OpenAI connector, which routes the key to `api.openai.com` and returns a `401`.

The error message compounds the confusion by telling the user to visit `platform.openai.com/account/api-keys`, which is factually wrong for this user's situation. There is zero graceful handling of `nvapi-` prefixed keys entering an OpenAI field.

**Root cause observed in screenshot:** User pasted an `nvapi-` NVIDIA key into the "Connect OpenAI" dialog → app routed it to OpenAI's endpoint → OpenAI returned `401 Incorrect API key provided: nvapi-4h***...FXiD` → error message incorrectly redirected user to `platform.openai.com/account/api-keys`.

## What Needs to Be Built

### 1. `NvidiaAdapter` — `apps/desktop/src/main/adapters/nvidia.adapter.ts`

Extend `BaseProviderAdapter`. NVIDIA NIM is OpenAI SDK-compatible, so this adapter instantiates the OpenAI client with a custom `baseURL`. Do **not** write raw fetch calls.

```typescript
import OpenAI from 'openai'
import { BaseProviderAdapter } from './base.adapter'

export class NvidiaAdapter extends BaseProviderAdapter {
  readonly providerId = 'nvidia_nim'

  private getClient(apiKey: string): OpenAI {
    return new OpenAI({
      apiKey,
      baseURL: 'https://integrate.api.nvidia.com/v1',
    })
  }

  async verify(credentials: ProviderCredentials): Promise<VerifyResult> {
    try {
      const client = this.getClient(credentials.apiKey)
      await client.models.list()
      return { success: true }
    } catch (err) {
      return { success: false, error: this.mapError(err) }
    }
  }

  async execute(
    request: TestRequest,
    credentials: ProviderCredentials,
    emit: IPCEmitter
  ): Promise<void> {
    const client = this.getClient(credentials.apiKey)
    // Delegate to the shared OpenAI streaming execution logic.
    // Model string format: "org/model-name"
    // e.g. "meta/llama-4-maverick-17b-128e-instruct"
    await this.executeOpenAICompatible(client, request, emit)
  }
}
```

> **Note:** Register `NvidiaAdapter` in `AdapterRegistry` alongside the existing OpenAI and Anthropic entries.

### 3. Preflight Key Format Validation

Before any network call is made in the `verify()` flow, add a client-side format check in the connection form. If the user pastes an `nvapi-` key into the **OpenAI** connector, intercept it and show a redirect nudge — do not let it hit `api.openai.com`.

**File:** `packages/shared-utils/src/validate-key-format.ts`

```typescript
const KEY_PREFIX_MAP: Record<string, string> = {
  'nvapi-':  'nvidia_nim',
  'sk-':     'openai',
  'sk-ant-': 'anthropic',
}

export function detectProviderFromKey(apiKey: string): string | null {
  for (const [prefix, providerId] of Object.entries(KEY_PREFIX_MAP)) {
    if (apiKey.startsWith(prefix)) return providerId
  }
  return null
}

export function isKeyFormatValid(apiKey: string, providerId: string): boolean {
  const detected = detectProviderFromKey(apiKey)
  return detected === null || detected === providerId
}
```

In the connection form's `onChange` handler, call `detectProviderFromKey`. If the detected provider differs from the current provider screen, show an inline warning **before** the user hits "Connect & Verify":

> ⚠️ This looks like an NVIDIA NIM key (`nvapi-`). [Switch to NVIDIA NIM connector →]

This prevents the exact failure mode visible in the screenshot.

## NVIDIA NIM — Technical Reference

| Property | Value |
|---|---|
| **API Base URL** | `https://integrate.api.nvidia.com/v1` |
| **SDK Compatibility** | OpenAI-compatible (use `openai` npm package with custom `baseURL`) |
| **Auth method** | Bearer token in `Authorization` header |
| **Key format** | Always prefixed `nvapi-` |
| **Key scope** | One key unlocks all 160+ models (no per-model or per-family keys) |
| **Key generation** | `https://build.nvidia.com/settings/api-keys` |
| **Free tier rate limit** | 40 RPM (displayed at top-right of `build.nvidia.com` UI) |
| **Credit system** | None — replaced by rate limiting; no expiry on free tier |
| **Model string format** | `org/model-name` e.g. `meta/llama-4-maverick-17b-128e-instruct` |
| **Verify endpoint** | `GET /models` (lightweight, same as OpenAI) |
| **Known issue** | Popular models frequently overloaded at peak — handle `503` and long timeouts gracefully; surface link to NVIDIA status page |

- [ ] The rate limit (40 RPM) is displayed in the evaluation drawer after each NVIDIA test run
- [ ] `detectProviderFromKey` utility has unit tests covering `nvapi-`, `sk-`, `sk-ant-` prefixes and unknown formats
- [ ] No NVIDIA-specific code exists inside `openai.adapter.ts` — all NVIDIA logic lives in `nvidia.adapter.ts`
- [ ] `503` responses from NVIDIA return a user-facing message with a link to the NVIDIA status page, not a generic error
