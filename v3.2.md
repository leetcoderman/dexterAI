# DexterAI v3.2 | Core Reference Documentation

This document provides a comprehensive technical overview of DexterAI, a desktop-native AI development environment designed for sovereignty, privacy, and high-performance agentic workflows.

---

## 🏗 Architecture Overview

DexterAI is built as an Electron application leveraging a multi-process architecture to ensure security and performance.

### 1. Main Process (Host)
- **Node.js Environment**: Manages the native system access, including the filesystem, OS Keychain (via `keytar`), and SQLite database lifecycle.
- **IPC Handlers**: Orchestrates the communication between the UI and native modules like `node-pty` (Terminal) and AI provider adapters.
- **Adapter Layer**: A standardized interface for multi-provider connectivity (OpenAI, Anthropic, Google, GitHub, etc.).

### 2. Renderer Process (UI)
- **React + Tailwind**: A high-performance, responsive interface built with modern web technologies.
- **Zustand State Management**: Handled via a centralized store (`/store/index.ts`) with persistent local storage.
- **Streaming Manager**: Manages real-time LLM token streams and UI reactivity.

### 3. Context Bridge (Preload)
- **Secure Sandbox**: Exposes a safe subset of native APIs to the renderer process via `window.dexterai`, preventing direct Node.js access from the UI.

## 🚀 Core Capabilities

### 🧠 Advanced Multi-Provider Chat
- **Unified Interface**: Single UI for testing and chatting with models from OpenAI, Anthropic, Google, Deepgram, NVIDIA NIM, and GitHub.
- **Dynamic Context Management**: Implements aggressive context trimming and summarization to ensure stability during extremely long conversations (128k+ tokens).
- **Multi-Modal Support**: Integrated ASR (Speech-to-Text) and TTS (Text-to-Speech) capabilities via Deepgram.

### 🤖 Autonomous Agent Workspace
- **Tool-Calling Engine**: Native support for LLM tool use, including filesystem manipulation and terminal execution.
- **IPC Approval Gates**: Destructive actions (like writing files or running commands) required explicit user approval via a UI-driven IPC handshake.
- **Infinite Turn Cycles**: Designed for long-running workflows with automated error recovery for rate limits and context overflows.

### 🖥 Native System Integration
- **Integrated Terminal**: Real-time terminal access powered by `node-pty`, allowing the AI to execute shell commands directly in the project environment.
- **Filesystem Mastery**: Robust traversal and searching of local project folders with built-in path traversal protection.
- **Security First**: API keys are stored exclusively in the OS-native Keychain. Application history and metadata are stored in a local SQLite database (WAL mode).

### 💾 Persistent Memory & Personalization
- **Automated Extraction**: Periodically extracts key facts and user preferences from conversations to build a persistent "Knowledge Profile."
- **Context Injection**: Relevant memories are dynamically injected into current AI prompts to ensure a personalized, context-aware experience.

## 🛠 Developer & Setup Guide

### Local Development
1. **Clone & Install**: `pnpm install`
2. **Setup Registry**: Ensure `registry.json` is updated with current model metadata.
3. **Run**: `npm run dev` to start the Electron environment.

### Deployment & Distribution
- **Build**: `npm run build` generates production-ready binaries for macOS, Windows, and Linux.
- **Registry Updates**: The model catalog can be updated remotely or locally via the internal Registry IPC.
